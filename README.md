# OG.Listener

Интерактивная аналитика официальной истории прослушиваний Spotify. Загрузите свой ZIP или JSON, чтобы исследовать любимые треки, исполнителей и то, как менялся ваш музыкальный вкус.

## Возможности

- Вся библиотека треков и исполнителей с обложками, размер которых зависит от прослушиваний или роста аудитории исполнителя.
- Топ-3, поиск без учёта регистра и пунктуации, фильтры по жанрам, датам, количеству и длительности прослушиваний.
- Графики личных прослушиваний и доступной истории аудитории, дата первого знакомства с треком или исполнителем.
- Единый плеер, который продолжает играть после закрытия карточки: доступные полные записи или обозначенные превью.
- Адаптивный интерфейс на русском и английском: язык браузера определяется автоматически, ручной выбор сохраняется.

## Быстрый запуск

Требуется **Node.js 22+**. Из корня репозитория:

```sh
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173/upload** и выберите официальный архив Spotify. Поддерживаются расширенная история `Streaming_History_Audio` и обычная `StreamingHistory`. Посетителю развёрнутого сайта нужны только браузер и собственный архив.

Локальная production-сборка:

```sh
npm test
npm run build
npm start
```

Сервер откроется на **http://127.0.0.1:3000**.

## GitHub Pages + Vercel API

Интерфейс публикуется на GitHub Pages, API - как Node.js Function на Vercel. API получает обложки, жанры, аудио и историю аудитории; личный архив разбирается в браузере. В корне Vercel открывается минимальная страница API со ссылкой на проверку `/healthz`; пользовательский интерфейс остаётся на Pages.

1. Импортируйте репозиторий в Vercel. В проекте выберите **Other**, Node.js **24.x** и каталог с `vercel.json`. В окружении **Production** задайте `CORS_ORIGINS=https://username.github.io` - адрес интерфейса **без пути репозитория**. Для своего домена укажите его origin. Конфигурация Vercel уже задаёт сборку API; `npm start` и `API_ONLY` для неё не нужны. Production-адрес API должен открываться без авторизации Vercel.
2. В репозитории GitHub откройте **Settings → Secrets and variables → Actions → Variables** и создайте переменную `VITE_API_BASE_URL` со значением `https://your-api.vercel.app`, **без `/api` и других путей**.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Единственный workflow публикации [static.yml](.github/workflows/static.yml) собирает и публикует только `dist/` при пуше в `main` или ручном запуске. Удалите старый `pages.yml` из репозитория, если он остался после предыдущей настройки.

Путь репозитория учитывается автоматически. На Pages загрузка архива открывается по `#/upload`, например `https://username.github.io/OG.Listener/#/upload`; локальный `/upload` продолжает работать. Ключи поставщиков задаются только на сервере API: все переменные `VITE_*` публичны.

Конфигурация подготовлена; сам деплой и адреса нужно настроить в Vercel и GitHub. Порядок настройки, проверка соединения и ограничения serverless - в [инструкции по развёртыванию](docs/deployment.md).

## Источники и настройки

Обложки и метаданные поступают из Spotify oEmbed, Deezer и Apple/iTunes; жанры дополняются MusicBrainz. Audius предоставляет доступные полные записи, Deezer и Apple - превью. История месячных слушателей запрашивается из Kworb и Internet Archive.

Для основных источников ключи не нужны. Дополнительные Last.fm, Jamendo и Chartmetric настраиваются через переменные окружения Vercel; локально - через `.env.local`. Имена переменных приведены в [.env.example](.env.example). Настоящие ключи не добавляйте в Git и переменные `VITE_*`.

## Личные данные и ограничения

Архив разбирается в браузере и не загружается на сервер. Личная история хранится в IndexedDB: каждый посетитель видит свою библиотеку. Она сохраняется на том же адресе сайта и в том же профиле браузера, пока браузерные данные не очищены; синхронизации между устройствами нет. Повторная загрузка архива заменяет библиотеку.

API получает названия и идентификаторы музыки для поиска метаданных, а для истории аудитории - исполнителя и дату первого прослушивания. Общий серверный кеш хранит публичные метаданные в оперативной памяти. Изображения и аудио браузер получает напрямую от поставщиков; приложение не создаёт их локальные файлы.

Покрытие внешних каталогов неполное. Жанры определяются по метаданным уже обработанных треков. Исторические слушатели доступны только для найденных исполнителей и реальных архивных дат; отсутствующие значения не выдумываются. При отсутствии полной записи плеер использует доступное превью.
