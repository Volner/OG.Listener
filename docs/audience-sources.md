# История аудитории исполнителей

[English](en/audience-sources.md)

OG.Listener автоматически запрашивает реальные наблюдения месячных слушателей Spotify из Kworb и Internet Archive. Это дополнительный набор данных: официальный архив прослушиваний пользователя не содержит историю аудитории исполнителей.

## Бесплатный источник: Kworb и Internet Archive

Сервер читает две общие таблицы Kworb: [основную](https://kworb.net/spotify/listeners.html) и [дополнительную](https://kworb.net/spotify/listeners2.html). Исполнитель сопоставляется по известному Spotify artist ID или однозначному совпадению имени в текущих таблицах. Неоднозначные совпадения не выбираются автоматически.

Для найденных исполнителей сервер получает реальные даты сохранения этих таблиц через Wayback CDX. Из доступного индекса выбираются до трёх снимков каждой страницы: ближайший перед первым прослушиванием, первый после него и последний после него. Один снимок может дать значения сразу нескольким исполнителям; отдельный обход архивных страниц для каждого имени не выполняется.

Дата наблюдения берётся из ответа источника: `Last-Modified` текущей таблицы, а для архивной - `Memento-Datetime` или фактической даты снимка в URL ответа. Страница без достоверной даты не превращается в точку графика. Для наблюдения сохраняются источник, дата, значение и ссылка на страницу.

Покрытие неполное. В таблицах представлены не все исполнители, а Internet Archive сохранял их нерегулярно. Если исполнитель отсутствует в текущем общем индексе, приложение не начинает отдельный поиск по всем его старым страницам. Это не доказывает отсутствие исторических данных вообще; автоматическая проверка текущей реализации ограничена доступными общими таблицами. Данные за конкретный год, включая 2019, не гарантируются.

## Автоматическая очередь и продолжение проверки

После чтения библиотеки браузер создаёт очередь всех исполнителей и отправляет их группами по 20. Видимые карточки получают приоритет. Закрытие карточки и смена фильтров не останавливают общую очередь; выполнение продолжается, пока приложение открыто.

Одна серверная партия Kworb имеет бюджет 40 секунд, тайм-аут отдельного запроса до 8 секунд и предел 12 новых запросов архивных таблиц. Это ограничения реализации, а не предоставленная источником квота. Необработанные даты возвращаются со статусом `deferred`; временные ошибки и ограничения частоты вызывают автоматический повтор с паузой. Успешно проверенное покрытие повторно используется в течение суток. Кеш таблиц API хранится в памяти конкретного экземпляра сервера и может исчезнуть при холодном старте Vercel.

Для продолжения между экземплярами API используется `archiveChecked`. Это максимум шесть идентификаторов вида `0:20240101000000`: номер одной из двух таблиц и дата снимка, до трёх на таблицу. Браузер сохраняет курсор вместе с результатом проверки в IndexedDB. В следующем запросе сервер сверяет эти идентификаторы с актуальным реальным индексом CDX и пропускает уже проверенные подходящие снимки. Поэтому новый экземпляр Vercel может продолжить работу, не начиная всегда с первых архивных страниц.

Курсор не содержит URL или количества слушателей и не создаёт наблюдений. Ранее полученные проверенные наблюдения и новые ответы объединяются только в браузере с проверкой исполнителя, источника и метрики. Числа из сохранённого результата не отправляются обратно API как доказательство исторических значений. Принудительная повторная проверка сбрасывает курсор; смена известного идентификатора исполнителя также исключает несовместимые накопленные наблюдения.

Состояние очереди и её результаты принадлежат браузеру пользователя. Серверный кеш публичных таблиц не является общей пользовательской библиотекой или постоянным фоновым заданием. После закрытия сайта запросы не продолжаются на сервере как отдельная задача; при следующем открытии приложение использует сохранённые результаты и заново планирует необходимую проверку.

## Коэффициент раннего открытия

Для Kworb исходным значением служит последнее реальное наблюдение не позднее первого прослушивания и не более чем за 31 день до него. Значение должно быть положительным. Для сравнения также требуется более позднее наблюдение того же источника и той же метрики.

```text
коэффициент = последнее известное число слушателей / исходное число слушателей
```

Например, рост с 13 до 2 000 000 даёт примерно 153 846×. Значения 530 000 / 500 000 дают 1,06×, а 320 / 300 - примерно 1,067×: второе отношение немного больше первого. Сортировка учитывает отношение, а не абсолютную прибавку.

Снимок после первого прослушивания не подставляется вместо исходного. Нулевое значение не используется как делитель. Если подходящего исходного снимка или более поздней точки нет, коэффициент остаётся неизвестным. Последнее известное значение может относиться к прошлой дате и не считается измерением прямо сейчас.

## График

График показывает одну последовательность месячных слушателей одного источника. Линия и градиентная заливка соединяют реальные наблюдения; они не добавляют ежедневные измерения между снимками. При единственной точке линия не строится.

Отдельная отметка показывает дату первого прослушивания. Если эта дата находится за пределами имеющихся наблюдений, шкала времени расширяется, но значения аудитории не экстраполируются. Подсказки относятся к существующим точкам. Отсутствующая история не заменяется нулями, популярностью, подписчиками или оценками.

## Дополнительный источник: Chartmetric

Адаптер Chartmetric уже реализован в API, но требует настроенного владельцем сервера `CHARTMETRIC_REFRESH_TOKEN` и подходящего платного доступа к истории. Для Vercel токен задаётся в переменных окружения проекта; локально - в `.env.local`. Его нельзя помещать в `VITE_*`, frontend или Git.

Адаптер запрашивает Spotify `listeners` начиная за 31 день до первого прослушивания, принимает только реальные числовые наблюдения и отбрасывает отмеченные источником интерполированные значения. Глубина истории зависит от исполнителя и доступа. Бесплатная браузерная очередь использует Kworb; добавление токена не переключает её автоматически на Chartmetric. Последовательности разных поставщиков не склеиваются для вычисления коэффициента.

Last.fm полезен для музыкальных метаданных, но его количество слушателей относится к Last.fm. Оно не заменяет месячных слушателей Spotify и не используется как такая последовательность на графике. Подробнее - в [документе Last.fm](lastfm.md).

## API и реализация

- `GET /api/audience/providers` - доступные провайдеры и состояние настройки.
- `POST /api/audience/resolve` - проверка группы исполнителей, наблюдения, покрытие и курсор продолжения.
- `POST /api/audience/import` - совместимый маршрут для меньшей группы исполнителей.

Формат маршрутов и ограничения описаны в [HTTP API](api.md), размещение - в [инструкции по развёртыванию](deployment.md). Реализация: [Kworb](../server/kworb.mjs), [адаптер аудитории](../server/audience.mjs), [браузерная очередь](../src/lib/useAudienceHistory.js), [подготовка графика](../src/lib/audience-series.js).

Справочные материалы: [Wayback CDX](https://github.com/internetarchive/wayback/tree/master/wayback-cdx-server), [Internet Archive](https://web.archive.org/), [исторические метрики Chartmetric](https://apidocs.chartmetric.com/reference/tag/artist/get/api/artist/id/stat/source).
