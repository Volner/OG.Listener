# Жанры и фильтры

OG.Listener определяет жанры по метаданным музыкальных каталогов. Звучание трека не анализируется, ИИ-классификация аудио не используется. Пользователю не нужно вручную размечать каждую песню.

## Источники жанров

| Источник | Какие данные используются | Условия |
| --- | --- | --- |
| Deezer | Жанры альбома найденного трека | Совпадают полное название и исполнитель после нормализации |
| Last.fm | Известные музыкальные стили из тегов трека; при их отсутствии - из тегов исполнителя | На API задан `LASTFM_API_KEY`; подробнее в [документации Last.fm](lastfm.md) |
| MusicBrainz | Жанры исполнителя из отдельного пространства `genres` | Другие источники не дали жанр; найден ровно один исполнитель с совпадающим именем |
| Apple Music / iTunes | `primaryGenreName` найденной песни | Дополнительный поиск при подготовке воспроизведения |

Жанр альбома или исполнителя может быть шире стиля конкретной песни. Теги Last.fm содержат также страны, настроения и личные пометки: в список жанров попадают только стили из ограниченного словаря приложения. Остальные теги остаются отдельными метаданными.

## Когда появляются данные

При просмотре библиотеки карточки ставятся в очередь: сначала запрашиваются обложки, затем дополнительные сведения. Запросы повторно не запускаются для каждого появления той же карточки; временные ограничения источников учитываются очередью.

Полного обхода всех треков во время импорта архива сейчас нет. Фильтр по жанру работает с уже полученными сведениями, а пункт «Жанр не определён» включает и ещё не обработанные треки, и песни без подходящих данных у источников. Если выбрать конкретный жанр, скрытые треки с неизвестным жанром не начинают автоматически сканироваться. Для расширения покрытия можно вернуться к «Все жанры» и просматривать библиотеку дальше.

В фильтрах показывается число треков с известным жанром относительно всей импортированной библиотеки. Дополнительные метаданные текущего просмотра находятся в памяти страницы; после перезагрузки часть сведений может запрашиваться снова. Это не влияет на сохранённую историю прослушиваний.

## Как сочетаются фильтры

1. Период и настройка «Считать прослушанным» отбирают события прослушивания. Начальная и конечная даты включаются целиком по UTC.
2. Жанр отбирает треки с подходящими метаданными. Поиск не учитывает регистр и знаки препинания.
3. В режиме исполнителей отобранные треки объединяются по исполнителю.
4. Диапазон количества прослушиваний применяется к итоговым трекам или исполнителям в выбранном периоде.

Поэтому при выборе жанра у исполнителя учитываются прослушивания только подходящих треков. График внутри карточки показывает всю историю выбранного трека или исполнителя с текущим порогом длительности, независимо от периода и жанра в библиотеке. Дата первого прослушивания относится к полному загруженному архиву.

Общая система синонимов и иерархия поджанров не реализованы: `Trap`, `Hip-Hop/Rap` и `Rap/Hip Hop` могут оставаться разными пунктами. Для тегов Last.fm есть небольшой словарь нормализации, например `rnb` → `R&B`.

Обложки подставляются по внешним HTTPS-ссылкам. Приложение не создаёт локальные файлы изображений или музыки; обычный HTTP-кэш браузера и CDN регулируется их настройками. О схеме API и ключах см. [API](api.md) и [развёртывание](deployment.md).
