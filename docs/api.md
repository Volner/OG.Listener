# HTTP API

API возвращает публичные музыкальные метаданные и внешние ссылки на изображения и аудио. ZIP/JSON личной истории разбирается в браузере и не отправляется на сервер. На GitHub Pages запросы идут на отдельный Vercel origin, заданный публичной переменной сборки `VITE_API_BASE_URL`; в обычном локальном режиме - на тот же origin.

Настройка окружения и CORS описана в [развёртывании](deployment.md). В `VITE_API_BASE_URL` указывается только HTTPS origin без `/api` и других путей. Для отдельного интерфейса его точный origin должен быть в `CORS_ORIGINS`. API не использует авторизационные cookies. Разрешённый preflight получает 204; `Retry-After` доступен браузеру через CORS. CORS ограничивает браузерные обращения и не является аутентификацией публичного API.

## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/catalog/resolve` | Метаданные партии из 1-100 треков |
| `GET /api/tracks/:id` | Метаданные одного трека и поиск доступного аудио |
| `GET /api/tracks?query=…` | Поиск кандидатов во внешнем каталоге; ответ `{ results, exactMatchRequired: true }` |
| `GET`, `HEAD /api/artwork/:id` | 302 на известную внешнюю обложку из кеша |
| `GET`, `HEAD /api/audio/:id` | 302 на известную полную запись или превью из кеша |
| `GET /api/audio/providers` | Список аудиоисточников и состояние их настройки |
| `GET /api/catalog/providers` | Состояние дополнительных источников метаданных без раскрытия ключей |
| `GET /api/audience/providers` | Источники истории аудитории и их ограничения |
| `POST /api/audience/resolve` | Проверенные наблюдения аудитории для 1-100 исполнителей |
| `POST /api/audience/import` | Совместимый маршрут той же задачи для 1-20 исполнителей |
| `GET /api/status` | Состояние экземпляра: `{ ok, storage: "memory", mediaFiles: 0 }` |
| `GET`, `HEAD /healthz` | Доступность серверного обработчика; GET возвращает `{ "ok": true }` |

Для POST требуется `Content-Type: application/json`. Пути `/api/upload`, `/api/catalog`, `/api/catalog/jobs`, `/api/catalog/pause`, `/api/catalog/resume` удалены и возвращают 410. Сервер не принимает архивы, не обслуживает серверную библиотеку пользователя и не создаёт задачи её импорта.

## Каталог и воспроизведение

Пример запроса; имя и название нужно заменить своими:

```json
{
  "tracks": [
    { "id": "local:example", "name": "Track title", "artist": "Artist name" }
  ],
  "details": true,
  "apple": false
}
```

У трека принимаются `id`, `name` (также допустим `title`), `artist` и необязательный `uri`. `id` - 22-символьный Spotify ID либо непрозрачный идентификатор с префиксом `local:`. Отправляйте названия вместе с ID: они нужны для точного поиска в других каталогах. Не используйте этот маршрут для передачи всей личной истории событий.

В партии `details` по умолчанию равен `true`, а Apple-поиск включается только при `apple: true`. `details: false` пропускает дополнительное обогащение жанрами. Полные записи партия не ищет: это отдельное действие воспроизведения.

Ответ имеет форму `{ entries, errors, storage: "memory", mediaFiles: 0 }`. `entries` - объект, где ключи соответствуют ID треков; `errors` содержит ошибки отдельных элементов. Успех HTTP-запроса не означает, что найдены все записи.

Запись может содержать `artwork`, `artistArtwork`, `genres`, `artistGenres`, `tags`, `artistTags`, `previewUrl`, `audioUrl`, `audioKind`, ссылки на страницы поставщиков и поля происхождения данных. Эти поля необязательны. `audioKind: "full"` обозначает проверенную полную запись; при наличии только превью возвращается `"preview"`. Пустые сведения не заменяются выдуманными значениями.

Для одного трека поддерживаются query-параметры `title`, `artist`, `apple`, `details`, `full`. В этом GET-маршруте последние три включены по умолчанию и отключаются строкой `false`. Быстрый запрос плеера:

```text
GET /api/tracks/:id?title=…&artist=…&full=true&details=false
```

Сегмент `:id` и query-значения кодируйте через `encodeURIComponent`. Это особенно важно для непрозрачных `local:` ID со слешами, пробелами, Unicode и знаком `%`. ID не являются путями файловой системы.

Медиамаршруты только перенаправляют на уже найденный и ещё действующий URL. Сначала выполните разрешение трека; отсутствие записи в кеше даёт 404. API не проксирует байты аудио или изображений и не сохраняет их в файлы. Подробнее - в [источниках аудио](audio-sources.md) и [жанрах](genre-filters.md).

## История аудитории

```json
{
  "provider": "kworb",
  "artists": [
    { "name": "Artist name", "firstPlayed": "2022-11-10T00:00:00.000Z" }
  ]
}
```

`provider` по умолчанию - `kworb`; дополнительный `chartmetric` требует серверного `CHARTMETRIC_REFRESH_TOKEN`. Каждому исполнителю нужны имя и корректная дата первого прослушивания не в будущем. Необязательные `artistId` или `spotifyArtistId` принимают 22-символьный Spotify artist ID.

Ответ содержит `provider`, `snapshots`, `coverage` и `errors`; Kworb также возвращает `summary`. В нём могут одновременно находиться найденные точки, отсутствие подходящего базового снимка и отложенная работа. Список источников не гарантирует покрытие каждого исполнителя или года.

Для Kworb поле `archiveChecked` каждой записи массива `coverage` содержит максимум шесть идентификаторов реальных архивных снимков вида `0:20240101000000`. При продолжении передайте этот список в `artists[].archiveChecked` вместе с прежней идентичностью исполнителя и первой датой. Сервер сверяет ID с CDX и пропускает уже завершённые обращения. Список не принимает произвольные URL или значения слушателей и сам по себе не доказывает наличие базового наблюдения.

Браузер сохраняет полученные наблюдения и объединяет их с новыми ответами того же источника и исполнителя. Это позволяет продолжать загрузку после холодного запуска Vercel без серверного хранения личной библиотеки. Формула роста, статусы покрытия и ограничения описаны в [истории аудитории](audience-sources.md).

## Ошибки, кеш и лимиты

JSON-тело ограничено 1 МиБ для каталога и 256 КиБ для аудитории, включая уже разобранное платформой тело. Некорректный JSON даёт 400, неподдерживаемый Content-Type - 415, слишком большой запрос - 413. Общие ошибки содержат `error`; аудитория дополнительно возвращает `code`, а ошибки ограничения могут содержать `retryAfterSeconds`.

При перегрузке возможен 429 с заголовком `Retry-After`; клиенту следует выдержать паузу. Параметры `API_*` ограничивают очередь и частоту запросов только внутри одного экземпляра API. Они не являются общей квотой Vercel или внешнего источника. Отдельные поставщики также могут ограничить запросы или временно не отвечать.

Кеши находятся в ограниченной оперативной памяти экземпляра, имеют сроки действия и объединяют одинаковую незавершённую работу. Они содержат публичные метаданные, не общую личную историю пользователей. Холодный запуск очищает кеши; HTTP-ответы API используют `Cache-Control: no-store`. Файлы архивов, конфигурация и исходники через API не раздаются.
