# HTTP API

Интерфейс GitHub Pages обращается к Node.js Function на Vercel. В сборке интерфейса `VITE_API_BASE_URL` задаёт только origin, например `https://your-api.vercel.app`; пути `/api/...` добавляются клиентом. В локальном интегрированном запуске API доступен на том же адресе, что и интерфейс.

API ищет публичные сведения о музыке и не хранит личную историю посетителей. Обложки и аудио возвращаются как внешние URL либо перенаправления; медиафайлы не проксируются и не записываются.

`vercel.json` направляет `/api/...` и `/healthz` в `api/index.js`; HTTP-порт и `npm start` на Vercel не используются. Для запросов с Pages задайте в окружении Vercel `CORS_ORIGINS=https://username.github.io`, без пути репозитория; несколько разрешённых origin разделяются запятыми. По умолчанию межсайтовый доступ не разрешён. CORS обрабатывает предварительный `OPTIONS` перед JSON-запросами и открывает браузеру заголовок `Retry-After`. Production-адрес должен быть публичным: защита авторизацией Vercel заблокирует запросы посетителей. Настройки — в [deployment.md](deployment.md).

| Маршрут | Назначение |
| --- | --- |
| `POST /api/catalog/resolve` | `{tracks, apple?, details?}`: до 100 треков, внешние URL и автоматические жанры |
| `GET /api/tracks/:id?title=...&artist=...&full=true&details=false` | Точный полный поток Audius/Jamendo при наличии, иначе превью Deezer/Apple |
| `GET /api/tracks?query=...` | Поиск по внешнему музыкальному каталогу |
| `GET /api/artwork/:id` | Перенаправление на внешний CDN обложек |
| `GET /api/audio/:id` | Перенаправление на доступное внешнее аудио |
| `GET /api/audio/providers` | Источники аудио и состояние их настройки |
| `GET /api/catalog/providers` | Состояние дополнительной интеграции Last.fm без раскрытия ключа |
| `GET /api/audience/providers` | Источники аудитории и их доступность без раскрытия ключей |
| `POST /api/audience/resolve` | Пакетная проверка исполнителей: найденные снимки, покрытие и сводка |
| `POST /api/audience/import` | Совместимый маршрут проверки одного или нескольких исполнителей |
| `GET /api/status` | Доступность сервиса без архивов, пользователей и списков треков |
| `GET /healthz` | Проверка доступности обработчика: `{ "ok": true }` |

Передавайте в запросе метаданных только необходимые публичные поля трека: `id`, `name`, `artist`, `uri`. Названия и идентификаторы в URL необходимо кодировать. Параметр `details=false` позволяет поиску аудио не ждать дополнительного определения жанров.

Для продолжения проверки Kworb поле исполнителя `archiveChecked` содержит до шести идентификаторов архивных снимков, возвращённых предыдущим ответом `coverage`. Сервер сверяет их с реальным индексом источника; они позволяют пропустить выполненную работу после холодного запуска. Это не URL и не наблюдения слушателей. Клиент сохраняет ранее полученные точки и объединяет их с новыми.

Кеш метаданных ограничен по размеру и сроку жизни, хранится в памяти экземпляра функции и не содержит принадлежности музыки пользователям. Новый экземпляр начинает с пустым кешем; устойчивого общего хранилища нет. Ответы API имеют `Cache-Control: no-store`. Конфигурация ключей находится только на сервере. Размер тела JSON ограничен до 1 MiB для метаданных и 256 KiB для аудитории; проверяются объявленный размер, поток или JSON, предварительно разобранный хостингом.

Ограничения очереди и частоты запросов задаются переменными `API_*` из [.env.example](../.env.example) и действуют отдельно в каждом экземпляре Vercel. При перегрузке API возвращает `429` с `Retry-After`; клиент должен дождаться указанного времени. Эти лимиты не ограничивают общие расходы или суммарные обращения к поставщикам при масштабировании. Настройки платформы описаны в [руководстве по развёртыванию](deployment.md).

Устаревшие `/api/upload`, `/api/catalog` и маршруты общих jobs/pause/resume отключены с HTTP `410`. Загрузка архива выполняется только в браузере. Production-сервер не выдаёт локальные экспорты, конфигурации, исходники и карты исходников.
