# Развёртывание OG.Listener

Интерфейс размещается на **GitHub Pages**, API — на **Vercel**. Посетителю нужны браузер и собственный ZIP/JSON Spotify. Архив разбирается в браузере; на API отправляются только сведения для поиска музыки и истории аудитории.

Конфигурации обеих площадок находятся в репозитории. Следующие действия выполняет владелец проекта; локальные изменения сами по себе сайт не публикуют.

## 1. Vercel API

1. Импортируйте GitHub-репозиторий в новый проект Vercel. **Root Directory** должен указывать на каталог с `package.json` и `vercel.json`: корень репозитория, если в него отправлено содержимое `site/`, либо `site`, если импортирован родительский репозиторий.
2. Выберите **Framework Preset → Other** и **Node.js → 24.x**. `vercel.json` отключает определение Vite-фреймворка и задаёт собственные команды установки, сборки и каталог вывода. Не переопределяйте их на `npm run build` или `dist`: интерфейс собирается отдельно на GitHub Pages.
3. В **Settings → Environment Variables** добавьте для окружения **Production**:

   | Переменная | Значение |
   | --- | --- |
   | `CORS_ORIGINS` | `https://username.github.io` либо origin собственного домена Pages |
   | `LASTFM_API_KEY` | Необязательно: ключ приложения для тегов Last.fm |
   | `JAMENDO_CLIENT_ID` | Необязательно: дополнительный каталог полных записей |
   | `CHARTMETRIC_REFRESH_TOKEN` | Необязательно: платный источник истории слушателей |

4. В **Settings → Deployment Protection** убедитесь, что **production-домен публичен** и не требует входа в Vercel. Для публичного API отключите Vercel Authentication для production; preview можно оставить защищённым. Не передавайте токены обхода защиты в JavaScript сайта. Разрешение только `OPTIONS` не открывает последующие `GET` и `POST`. Настройка описана в [документации Vercel Authentication](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication).
5. Выполните Deploy и сохраните постоянный production-origin, например `https://your-api.vercel.app`. В новом приватном окне проверьте `https://your-api.vercel.app/healthz`: ожидается JSON `{ "ok": true }` без страницы входа.

`CORS_ORIGINS` содержит точные origin: протокол, имя хоста и при необходимости порт, **без пути репозитория, `/` в конце и подстановок `*`**. Для `https://username.github.io/OG.Listener/` значение — `https://username.github.io`. Несколько origin разделяются запятыми. При пустом значении доступ с отдельного интерфейса Pages не разрешён.

Vercel вызывает `api/index.js` для `/api/...` и `/healthz`; функция использует встроенные модули Node. Подготовка создаёт пустой каталог `.vercel-static` для статического вывода: исходники, архивы и интерфейс туда не копируются. **`npm start`, `API_ONLY`, `HOST`, `PORT` и `TRUST_PROXY` на Vercel не нужны**. Эти параметры остаются для локального сервера. Адрес посетителя определяется из проверенного платформенного заголовка только при работе в среде Vercel.

Все ключи поставщиков задавайте в окружении Vercel, а локально — в игнорируемом `.env.local`; уже заданное окружение имеет приоритет. Значения `VITE_*` для секретов не подходят. После изменения переменных Vercel создайте новый deployment. Полный список настроек — в [`.env.example`](../.env.example).

## 2. GitHub Pages

1. В **Settings → Secrets and variables → Actions → Variables** создайте **repository variable** `VITE_API_BASE_URL` со значением `https://your-api.vercel.app`. Указывайте только HTTPS-origin API, без `/api`, других путей, параметров и ключей.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main` либо запустите workflow [Deploy to GitHub Pages](../.github/workflows/pages.yml) вручную на вкладке **Actions**.

Workflow устанавливает зависимости, проверяет проект, выполняет `npm run build:pages` и публикует только `dist/`. `configure-pages` передаёт базовый путь для project Pages и своего домена. Для пользовательского домена сначала настройте его в Pages и DNS; ручная правка путей в коде не требуется.

В Pages-сборке используется маршрут `#/upload`, например `https://username.github.io/OG.Listener/#/upload`. Обновление страницы работает без серверных SPA-перенаправлений. Локальный `/upload` сохранён.

`VITE_API_BASE_URL` встраивается в JavaScript при сборке и виден посетителям. **Все `VITE_*` публичны.** После изменения адреса API запустите новую сборку Pages; при изменении домена интерфейса обновите также `CORS_ORIGINS` в Vercel и выполните повторный деплой API.

### Проверка после публикации

- Откройте `#/upload` на адресе Pages, обновите страницу и загрузите собственный архив.
- Проверьте запросы к production-origin Vercel в браузере: `OPTIONS` и JSON-запросы должны проходить без CORS-ошибок и перенаправлений на авторизацию. Обложки, жанры, аудио и история аудитории доступны в пределах покрытия источников.
- Во втором профиле браузера должна открываться пустая личная библиотека. Архив первого профиля через API не передаётся.

`/healthz` проверяет доступность обработчика, а не всех музыкальных источников. Без доступного API локальная статистика архива работает, но новые метаданные, аудио и история аудитории не загрузятся.

## Ограничения Vercel и нагрузки

В `vercel.json` включён Fluid Compute и задан `maxDuration: 300` секунд для единственной функции. На Hobby это текущий максимальный срок одного вызова с Fluid Compute. Источник: [ограничения длительности Vercel Functions](https://vercel.com/docs/functions/configuring-functions/duration).

Приложение ограничивает тело JSON-запроса до **1 MiB**; архивы через API не принимаются. Дополнительно действует ограничение платформы **4,5 MB** для тела запроса или ответа функции. Аудио и обложки передаются как внешние URL, их содержимое через функцию не проходит. Источник: [Vercel Functions Limits](https://vercel.com/docs/functions/limitations).

Кеши и очереди живут только в памяти конкретного тёплого экземпляра. Холодный запуск начинает с пустым кешем; разные экземпляры не разделяют состояние. По умолчанию в одном экземпляре разрешены 12 активных API-запросов, 24 ожидающих, до 5 секунд ожидания; на IP — пополнение 120 запросов в минуту и запас 30. Настройки `API_*` приведены в `.env.example`. При перегрузке API возвращает `429` и `Retry-After`; клиент метаданных ждёт и повторяет запрос.

Отложенная проверка Kworb не зависит от тёплого кеша: браузер сохраняет небольшой список уже проверенных архивных снимков и передаёт его при повторе. Новый экземпляр сверяет эти идентификаторы с индексом Internet Archive и продолжает оставшиеся проверки. Полученные наблюдения объединяются в браузере; значения слушателей и личная статистика обратно в API не отправляются.

Эти ограничения **не задают общий лимит всех экземпляров**, бюджет Vercel или суммарную квоту источников. Для большой нагрузки потребуется общее ограничение обращений и, при необходимости, внешний кеш публичных метаданных. Автоматическое масштабирование функции само по себе не устраняет лимиты Deezer, Apple, Kworb и Internet Archive. Пропускная способность для 10 000 одновременных пользователей не измерена.

Следите за использованием ресурсов и настройками расходов проекта. Бесплатный тариф имеет квоты, а платный — тарификацию использования; проект не гарантирует бесплатную работу при произвольной нагрузке. Актуальные условия: [Vercel pricing](https://vercel.com/docs/pricing) и [Spend Management](https://vercel.com/docs/pricing/spend-management).

Покрытие данных остаётся частичным: жанры известны для обработанных треков; история аудитории ограничена реальными снимками Kworb/Internet Archive; полная запись доступна при точном совпадении в открытом каталоге, иначе используется обозначенное превью.

## Локальная разработка

Требуется Node.js 22+; для соответствия Vercel используйте 24.x. Обычный режим объединяет интерфейс и API на одном origin. Оставьте `API_ONLY=false`, не задавайте внешний `VITE_API_BASE_URL` и выполните:

```sh
npm ci
npm run dev
```

Адрес — `http://127.0.0.1:5173/upload`. Для локальной production-проверки:

```sh
npm test
npm run build
npm start
```

Адрес — `http://127.0.0.1:3000/upload`. Локальный `npm start` с `API_ONLY=true` запускает только API без `dist/`. `HOST` и `PORT` задают локальный адрес; `SIGTERM`/`SIGINT` останавливают процесс с ограниченным ожиданием. За локальным прокси `TRUST_PROXY` принимает точные доверенные IP либо `loopback`; прокси должен перезаписывать `X-Real-IP`, `X-Forwarded-For` игнорируется.

Для проверки Pages-сборки создайте игнорируемый файл `.env.pages.local`:

```dotenv
VITE_API_BASE_URL=https://your-api.vercel.app
VITE_BASE_PATH=/OG.Listener/
```

Замените имя репозитория и адрес API своими значениями. Затем выполните:

```sh
npm run build:pages
npm run preview -- --mode pages
```

Откройте выведенный Vite адрес с базовым путём, например `http://127.0.0.1:4173/OG.Listener/#/upload`. Для запросов из preview временно добавьте `http://127.0.0.1:4173` в `CORS_ORIGINS` API и выполните повторный деплой Vercel. В GitHub Actions `VITE_BASE_PATH` устанавливается автоматически из настроек Pages.

## Личные данные

Личная история и рассчитанная статистика остаются в IndexedDB браузера на адресе интерфейса Pages. Сервер не хранит принадлежность музыки пользователю. При загрузке карточек API получает идентификаторы, названия треков и исполнителей; для графика аудитории — исполнителя и дату первого прослушивания. Общий кеш содержит только публичные сведения о музыке и снимки источников.

У приложения нет автоматического удаления личной истории: она доступна при следующем посещении в том же браузере. Очистка данных браузера, другой профиль, устройство, домен, протокол или порт означают другую локальную библиотеку. При переходе с localhost на постоянный HTTPS-домен архив нужно один раз загрузить на новом адресе. «Загрузить архив» обновляет библиотеку целиком.

В `public/` разрешён только favicon. Архивы, личная история, ключи и резервные копии не входят в репозиторий и сборку. Сборка останавливается при появлении незаявленного публичного файла. На Pages загружается только `dist/`, в статический вывод Vercel — пустой каталог. Не включайте запись тел запросов и музыкальных query-параметров в собственные логи или внешнюю аналитику.
