# Источники аудио

Все доступные записи воспроизводятся в одном встроенном HTML-аудиоплеере. Он находится на уровне приложения и продолжает играть после закрытия карточки, поиска, переключения фильтров или режима библиотеки. Закрытие вкладки или перезагрузка страницы останавливает воспроизведение.

## Подключённые источники

| Источник | Формат | Настройка API |
| --- | --- | --- |
| Audius | Полная открытая запись, если найдено точное совпадение | Текущая интеграция использует публичные запросы с `app_name=OG.Listener` |
| Jamendo | Полная запись из доступного каталога | Необязательный серверный `JAMENDO_CLIENT_ID` |
| Deezer | Превью, обычно около 30 секунд | Отдельный ключ в текущей интеграции не нужен |
| Apple Music / iTunes | Превью | Отдельный ключ в текущей интеграции не нужен |

Полные записи ищутся при нажатии «Слушать», а не для каждой появившейся обложки. Audius и настроенный Jamendo проверяются параллельно; при успешных ответах приоритет у Audius. Если полная запись не найдена или её поток не воспроизводится, плеер использует независимо сопоставленное превью. Плашка плеера указывает фактический формат и источник, а ссылка ведёт на страницу записи у поставщика.

Наличие трека в истории Spotify не гарантирует его наличие в другом каталоге. Эти интеграции не предоставляют полный каталог Spotify; иногда аудио не будет найдено вообще.

## Как сопоставляются записи

Название и имя исполнителя сравниваются полностью после нормализации регистра, диакритики, пунктуации и пробелов. Другая версия с отличающимся названием - например, live или remix - не подставляется вместо исходной песни. Совпадение названия само по себе недостаточно.

Для Audius дополнительно проверяются признаки доступности потока: закрытые, удалённые, скрытые и требующие специальных условий записи исключаются. Среди совпадений предпочтение отдаётся проверенному аккаунту исполнителя; неоднозначные совпадения нескольких аккаунтов отклоняются. Это уменьшает ошибки сопоставления, но не заменяет идентификацию по Spotify ID или ISRC. Jamendo также требует точного совпадения и одного аккаунта исполнителя среди результатов.

Полная версия определяется проверенным ответом конкретного источника. Расширение ссылки или продолжительность файла сами по себе не превращают превью в полную запись.

## Поведение плеера и хранение

Повторное нажатие воспроизведения той же песни переключает паузу; выбор другой песни меняет запись. Ползунок использует реальную длительность медиа и допускает перемотку. В начале и конце предусмотрено плавное изменение громкости; возможность программно менять громкость зависит от браузера, особенно на мобильных устройствах. Есть интеграция с Media Session там, где она поддерживается.

API возвращает внешние ссылки на аудио, а браузер обращается к потоку поставщика напрямую. `/api/audio/:id` перенаправляет на внешний адрес и не проксирует медиафайл. Ни сервер, ни приложение не сохраняют песни и обложки в файловую систему, IndexedDB или Cache Storage; обычный сетевой кэш браузера и CDN может работать независимо.

Поиски и их результаты имеют ограниченный кэш в памяти экземпляра API, включая кратковременное кэширование отсутствующих записей. Холодный запуск Vercel очищает этот кэш. Истекающие ссылки могут потребовать нового поиска. Приложение использует поток `audio` Jamendo и не предоставляет функцию скачивания `audiodownload`.

`GET /api/audio/providers` показывает источники и состояние настройки без раскрытия ключей. Запрос `GET /api/tracks/:id?title=...&artist=...&full=true&details=false` ищет аудио без ожидания дополнительной жанровой разметки. Секреты задаются только на API: см. [развёртывание](deployment.md) и [описание API](api.md).

## Документация поставщиков

- [Audius API](https://docs.audius.co/api/).
- [Jamendo: tracks](https://developer.jamendo.com/v3.0/tracks).
- [Apple iTunes Search API](https://performance-partners.apple.com/search-api).

Spotify Web Playback SDK и SoundCloud в текущий плеер не подключены. Last.fm используется для [метаданных и жанров](lastfm.md), а не как источник полных аудиофайлов.
