# Техническая документация OG.Listener

Здесь описаны устройство приложения, источники данных, локальный запуск и публикация. Обзор возможностей для посетителя находится в [README проекта](../README.md).

## Как проходят данные

1. Пользователь выбирает официальный архив Spotify в ZIP или JSON. Поддерживаются расширенная история `Streaming_History_Audio` и обычная `StreamingHistory`.
2. Браузерный Worker разбирает архив и преобразует записи в библиотеку треков, исполнителей и событий прослушивания. Личная история сохраняется в IndexedDB текущего браузера.
3. Интерфейс вычисляет статистику по этой истории и запрашивает у API недостающие публичные метаданные. Обложки и жанры подгружаются по мере просмотра, история аудитории - через фоновую очередь, полные записи - при нажатии «Слушать».
4. API сопоставляет названия и идентификаторы с внешними каталогами и возвращает метаданные и ссылки. Браузер получает изображения и аудио по внешним URL.

Интерфейс публикуется на GitHub Pages, API работает как Node.js Function на Vercel. При локальной разработке Vite подключает локальный API. Команды, переменные окружения, настройка CORS и workflow описаны в [инструкции по развёртыванию](deployment.md).

## Личная история и общие метаданные

Архив и полная история прослушиваний не отправляются на API. Запросы метаданных содержат названия и идентификаторы музыки; для истории аудитории передаются также исполнитель, дата первого прослушивания и ограниченный список идентификаторов уже проверенных архивных снимков. Личные события прослушивания и значения слушателей из браузера не используются как данные внешнего источника.

Каждый посетитель видит библиотеку из своего профиля браузера и текущего адреса сайта. Она не синхронизируется между устройствами или доменами. Автоматического срока удаления нет, но очистка браузерных данных удалит библиотеку. Повторная загрузка архива заменяет её.

Серверный кеш содержит публичные метаданные в памяти одного экземпляра API. Он может обслуживать одинаковые запросы разных посетителей и исчезает при холодном запуске; личные библиотеки в нём не хранятся. Приложение не создаёт локальные файлы обложек или музыки. Обычный HTTP-кеш браузера и CDN работает независимо.

## Источники данных

| Источник | Что используется | Условия и ограничения |
| --- | --- | --- |
| Spotify oEmbed | Ссылки на обложки | Нужна доступная запись Spotify; история пользователя не запрашивается |
| Deezer | Обложки, жанры альбомов, превью | Используется сопоставление названия и исполнителя; покрытие неполное |
| Apple Music / iTunes | Дополнительные обложки, превью, основной жанр | Дополнительный поиск при подготовке воспроизведения |
| MusicBrainz | Жанры исполнителя | Запасной источник при однозначном совпадении исполнителя |
| Audius | Полные открытые записи | Проверяется совпадение трека и доступность потока; полного покрытия Spotify нет |
| Jamendo | Дополнительные полные записи | Необязательный серверный `JAMENDO_CLIENT_ID` |
| Last.fm | Теги треков и исполнителей, известные музыкальные стили | Необязательный серверный `LASTFM_API_KEY`; теги не являются анализом аудио |
| Kworb + Internet Archive | Реальные наблюдения месячных слушателей Spotify | Только найденные исполнители и доступные снимки; даты разреженные |
| Chartmetric | Дополнительная история месячных слушателей | Необязательный платный доступ и серверный `CHARTMETRIC_REFRESH_TOKEN`; глубина зависит от доступа и исполнителя |

Обязательных ключей для основных источников нет. Дополнительные интеграции настраивает владелец API через окружение Vercel или локальный `.env.local`; посетителю ключи не нужны. Имена переменных перечислены в [`.env.example`](../.env.example). Секреты остаются на сервере: все переменные `VITE_*` входят в публичную сборку интерфейса.

Доступность источника не гарантирует данные для каждого трека или исполнителя. Если полная запись не найдена, плеер может использовать обозначенное превью. Отсутствующие исторические значения аудитории не оцениваются и не подменяются другой метрикой.
